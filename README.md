# HS Tariff Agent

跨境卖家的**HTS 编码归类 + 关税计算 + 美欧合规问答**系统。复刻并改进 Zhang et al. 2026（arXiv:2605.14857）的确定性智能体工作流：控制流由代码固定，LLM 只在窄阶段调用——每个中间结果可检查、可归因、可复现。

## 为什么是确定性工作流（而不是 ReAct agent）

HS 归类是在 **~1250 个封闭集合品目上做排序决策**：错一个码就是错，需要可归因的失败分析。端到端提示 LLM "给这个商品归类" 会漏掉章注里的排除条款（如 3926 排除已具体列名的塑料制品）；自规划 agent 的多跳决策不可复现、错误无法定位。确定性漏斗让每个错误都能标注到首个丢失阶段（stage attribution），这是可迭代的工程，而不是玄学调 prompt。

合规问答则是开放域事实检索——"玩具进美国要什么认证"——答案由知识库覆盖面决定，RAG 就是标准解法。**两类任务两套架构**，这是刻意的范围控制。

## 架构

```
                    ┌─ 离线知识工程（每版 HTS 构建一次）─────────────┐
                    │ exportList 全表 → 品目/子目层级索引            │
                    │ 章注/类注 → 类型化条款 (clauses.jsonl, 2693 条) │
                    │ BM25(词干化) ⊕ BGE bge-base-en-v1.5 稠密 → RRF │
                    └──────────────────────────────────────────────┘
                                        │
在线六阶段漏斗 (~64 → ~10 → 3 → 1)      ▼
S1 属性抽取(LLM, 固定 schema) → S2 双查询检索 RRF + 残差品目注入
  → S3 L1 粗排(LLM 只看品目条文) → S4 L2 精排(加载类注/章注，允许仅凭
  排除条款降级, note-triggered) → S5 子目解析(GIR 6, 子树校验) → S6 评分+逐字引用

关税模块: 多国税率查询（美国/英国/日本/加拿大/澳大利亚，全部官方源）
合规模块: 策展知识库 BM25⊕dense RAG + DeepSeek 带引用生成
```

### S2 残差品目注入（本项目的检索创新点）

GIR 1(b) 逻辑：商品与任何具体品目条文都不匹配时落入 "Other articles of X" 残差品目（3926/6307/4421…）。这类品目的条文文本（"其他塑料制品"）与商品描述语义距离极远，纯检索永远排不上来——评测里 48% 的错误是这种 S2 漏召回。修复：top-8 候选所在章的残差品目确定性注入候选集，gold 召回 **82.9% → 97.1%**。

| 归因 | v2 | v1 | 论文 |
|---|---|---|---|
| S2 检索未召回 | 21.7% | 48.0% | — |

修复 S2 后错误分布**收敛到论文的主错误模式**（65.2% vs 论文 65% 的 L2-kept-not-rank1）——说明剩余差距在精排排序质量，与论文结论一致。据此做了 S4 v3（章注按章分组去重、context 增补子目文本承载材质判据、prompt 注入 GIR 原则化的"客观特征优先于商品名"判据：珠宝按材质组成、机器按主功能），抽查验证：智能手表 8517-vs-9102 旗舰案例修复、哨兵无回归；完整 before/after 留待全量评测。分布图：`artifacts/attribution.png`。

**口径声明**：本地 HTS 数据版本与 HSCodeComp 标注年份可能不一致；评测为 70 条抽样而非全量 632；special 税率按 2 字母协定代码粗判，A* / A+ 等计划代码细则不展开。

## 快速开始

```bash
pip install -r requirements.txt
export HF_ENDPOINT=https://hf-mirror.com   # 国内镜像
# .env: DEEPSEEK_API_KEY=...

python -m src.ingest.build_index            # 若 artifacts/ 已随 repo 提供可跳过
python -m src.eval.run_eval 70              # 评测（断点续跑）
python -m src.eval.run_eval report          # 汇总指标
python -m src.eval.attribution              # 错例归因 + 分布图

streamlit run src/app/streamlit_app.py      # 三 tab 前端（归类/税率/合规）
```

单条调试：`python -m src.stages.pipeline "TPU hydrogel screen protector"`；税率：`python -m src.tariff.rates 6101.20.00 --value 1000 --kg 4`。

## 错误分析示例（20 例精选 → README 展示 3 例）

1. **智能手表**（gold 8517 vs 预测 9102）：带蜂窝通话的智能手表按功能归 8517（通信设备），纯计时归 9102——v2 检索修复后 8517 已稳定进入候选与 top-3，但 S4 精排仍按 "watch" 字面排 9102 第一。反映精排对"功能 > 类名"的 GIR 1(a) 原则利用不足，是当前主错误模式（kept_not_rank1）的典型样本。
2. **注射器针头**（gold 8207）：gold 在 top-200 检索里都不存在——描述里没有任何 "interchangeable tool" 语义线索，属于知识盲区而非排序问题（S2 不可修复型）。
3. **软胶美甲贴**（gold 3926）：v1 检索召回 3304 化妆品与 9615 梳子；残差注入补进 3926 后由 S4 正确排第一——残差机制的直接受益案例。

## 范围与非目标

- 关税：不做协定优惠的智能匹配（special 列只做国家代码粗判）；国家覆盖 = 美国（深度：三列税率+税种分解计算）/ 英国（GOV.UK API+缓存）/ 日本（7392 线）/ 加拿大（12326 线）/ 澳大利亚（6837 线），其余国家调研记录见 `src/tariff/countries.py` 头注释（KR 需韩国侧注册；SG/TH/BR 无机器可读源；IN/MX 网络不可达；EU 无公开 API）
- 合规：纯 RAG，不做确定性管线；知识库 11 篇，聚焦**运动相机/消费电子及配件**品类（自拍杆、保护镜、充电器、备用电池）：品类决策表 + FCC/CE(EMC·LVD·RED·RoHS)/WEEE·电池法规·锂电运输/Prop 65/德法 EPR/GPSR 等专项；策展流程 = 半自动抓取 → 结构化 → 人工审核（`review_status: draft` 标记未审核条目）
- 全量 632 条评测：70 条抽样已复现论文归因结构，全量跑待做（预算 ~6M tokens）
